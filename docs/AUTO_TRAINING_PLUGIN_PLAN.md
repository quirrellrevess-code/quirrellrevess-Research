# 自动训练插件开发计划

## 当前结论

URADLL 已提供插件加载机制、请求/响应分析器和 HTTP 路由扩展点。服务器将游戏通知数据解码为 JSON，再调用注册的分析器。已观察到的通知路由是接收游戏发来的 `/notify/request` 与 `/notify/response`，不能据此推断插件已具备向游戏发出操作的能力。

## 里程碑

- **M1 状态采集**：独立插件接入响应分析器，保存回合、剧本、体力、心情、属性和可用指令摘要。
- **M2 数据建模**：按剧本分别识别训练项目、失败率、训练伙伴、比赛安排、事件及目标。
- **M3 决策引擎**：实现可解释、可单元测试的规则评分，先输出建议而不执行。
- **M4 离线回放**：使用脱敏状态样本比较决策，检查缺失字段、未知剧本和异常状态。
- **M5 行动通道**：研究客户端实际操作协议与合法可用的执行方式；在验证成功前不提交自动操作。
- **M6 受控运行**：加入幂等保护、动作结果确认、超时恢复、停止开关和审计日志。

## 当前提交

`components/` 是 M1 的初始实现，尚未在用户环境编译或运行。它只观察响应并写入 JSONL，不会点击、提交或修改游戏操作。

## 验收标准

1. 使用目标 URA 版本可成功编译并加载插件。
2. 收到真实培育状态响应后，日志字段可被稳定解析。
3. 采集失败不会中断 URADLL 主流程。
4. 对未知剧本、缺失字段和异常 JSON 采取保守处理。
5. 自动执行功能必须有独立验证的行动通道与明确的停止机制。
